# 쇼핑 연동 조사 (오늘의집 · 네이버쇼핑 · 쿠팡)

조사일: 2026-11-17. 담당: 쇼핑. 검색에는 "책상" 같은 일반 단어만 썼어요(사용자 정보는 보내지 않았어요).

## 한 줄 결론

- **지금 바로 되는 것**: 검색어마다 오늘의집·네이버쇼핑·쿠팡 **검색 결과로 가는 링크**(`shopLinks`). 사용자가 직접 눌러서 방문하는 것이라 문제가 없어요.
- **안 되는 것**: 오늘의집 페이지나 내부 JSON을 프로그램이 자동으로 읽어 오는 것. robots.txt와 약관이 막고 있어서 **구현하지 않았어요.**
- **실시간 가격**: 유일한 합법 후보였던 네이버 쇼핑 검색 오픈 API가 **2026-07-31에 종료**됐어요(5절). 그래서 지금은 실시간 가격을 받을 합법적인 무료 경로가 없고, 화면은 "시연용 예상 가격 + 쇼핑몰 링크"로 보여주는 것이 맞아요.
  서버 코드(`server/shop.js`)는 규약대로 만들어 두었지만 기본 상태는 꺼져 있어요(503).

## 1. 오늘의집 공식 API가 있는지

| 확인한 것 | 결과 |

## 2. robots.txt

2026-11-17에 `curl`(기본 User-Agent 그대로, 속이지 않음)로 받은 내용이에요. robots.txt는 로봇이 읽으라고 둔 파일이라 이것만 직접 받았어요.

**https://ohou.se/robots.txt**

```
User-agent: *
Disallow: /

User-agent: Googlebot
... (Bingbot, Yeti, Daum, Claude-SearchBot, OAI-SearchBot, PerplexityBot, Claude-User 등 이름이 적힌 검색 로봇)
Crawl-delay: 1
Disallow: /
Allow: /$
Allow: /productions/*/selling
Allow: /productions/feed
Allow: /store
Allow: /store/category?*
...
```

**https://store.ohou.se/robots.txt**

```
# *
User-agent: *
Disallow: /

# Googlebot
User-agent: Googlebot
Disallow: /api/
... (이름이 적힌 검색 로봇은 모두 Disallow: /api/)
```

읽는 법:

- 이름이 적히지 않은 프로그램(= 우리 서버)은 `User-agent: *` → **`Disallow: /`**, 즉 모든 경로가 금지예요.
- 검색 엔진 로봇에게만 `/productions/feed`(스토어 검색) 같은 일부 경로를 열어 두었고, 그 로봇들에게도 `store.ohou.se/api/`(내부 JSON)는 금지예요.
- 실제로 robots.txt가 허용한 도구(Claude 웹 가져오기)로 `https://ohou.se/productions/feed?query=책상`, `https://store.ohou.se/search?keyword=책상`을 열어 보았더니 둘 다 **HTTP 403**(봇 차단)이었어요. 차단을 우회하는 시도는 하지 않았어요.

## 3. 오늘의집 이용약관

- 약관 페이지: https://ohou.se/usepolicy ("고객 이용 약관"), https://ohou.se/policy/use_policy_4 ("오늘의집 서비스 이용 약관").
- 2절과 같은 이유로 약관 페이지를 프로그램으로 직접 열지는 못했어요. 아래는 **검색 엔진이 보여준 내용**이라 글자 하나하나가 원문과 같은지는 확인하지 못했어요(검색 엔진에 저장된 판은 약 2년 반 전 것).
  - 제12조(회원탈퇴 등) 3항: "회원이 다음 각 호의 사유에 해당하는 경우, 오늘의집은 사안의 경중에 따라 회원자격을 제한 및 상실시키거나 재이용에 제한을 둘 수 있습니다."
  - 그 사유 가운데 하나로 **크롤링, 리버스 엔지니어링, 디컴파일, 자동접속 프로그램 등 정상적이지 않은 방법으로 서비스를 이용해 서버에 부하를 주거나 정상적인 서비스를 방해하는 경우**가 들어 있어요(요약).
- 최신 약관은 사용자가 브라우저로 https://ohou.se/usepolicy 를 열어 확인해 주세요.

→ 판단 규칙(robots.txt가 허용하고 **동시에** 약관이 금지하지 않을 때만 자동 수집)을 적용하면, robots.txt 하나만으로도 **자동 수집은 불가**예요. User-Agent를 속이거나, 봇 차단을 우회하거나, 화면 없는 브라우저로 여는 방법은 쓰지 않아요.

## 4. 오늘의집 검색 링크 주소

| 후보 | 근거 | 결정 |
|---|---|---|
| `https://ohou.se/productions/feed?query=<검색어>` | ① robots.txt에 `Allow: /productions/feed`가 지금도 있어요. ② 검색 엔진에 `m.ohou.se/productions/feed?query=%EC%9A%B0%EC%9D%98...` 같은 주소가 "우의의 검색결과 3,737개", "미니어처의 검색결과 8,133개" 제목으로 여러 개 색인돼 있어요. | **사용** |
| `https://store.ohou.se/search?keyword=<검색어>` | 색인된 주소나 문서에서 근거를 찾지 못했어요(`store.ohou.se/goods/<번호>` 상품 주소만 확인). | 쓰지 않음 |
| `https://ohou.se/search/index?query=<검색어>` (통합 검색) | 색인된 근거를 찾지 못했어요. | 쓰지 않음 |

주의: 봇 차단(403) 때문에 프로그램으로 최종 확인은 못 했어요. **사용자가 브라우저에서 한 번 눌러 확인**해 주세요. 주소가 바뀌었다면 `src/shop.js`의 `SHOPS` 첫 줄만 고치면 돼요.

다른 링크: 네이버쇼핑 `https://search.shopping.naver.com/search/all?query=`, 쿠팡 `https://www.coupang.com/np/search?q=`. 널리 쓰이는 주소 형식이지만 이것도 직접 요청해서 확인하지는 않았어요.

## 5. 네이버 쇼핑 검색 오픈 API — 종료됨

공식 문서(https://developers.naver.com/docs/serviceapi/search/shopping/shopping.md)의 규격은 이래요.

- 요청: `GET https://openapi.naver.com/v1/search/shop.json`, 헤더 `X-Naver-Client-Id`, `X-Naver-Client-Secret`.
- 파라미터: `query`(필수, UTF-8), `display`(기본 10, 최대 100), `start`, `sort`(`sim` 정확도순 기본 / `date` / `asc` / `dsc`), `filter`, `exclude`.
- 응답 항목: `title`("이름에서 검색어와 일치하는 부분은 <b> 태그로 감싸져 있습니다."), `link`, `image`, `lprice`("최저가. 최저가 정보가 없으면 0 을 반환합니다."), `mallName`("쇼핑몰 정보가 없으면 네이버 를 반환합니다.") 등.
- "쇼핑 검색은 검색 API를 사용하며, 검색 API의 하루 호출 한도는 25,000회입니다."

**하지만 지금은 쓸 수 없어요.** NAVER API 서비스 이용약관(https://developers.naver.com/products/terms/, 2026년 10월 7일 개정) 부칙:

> 제2조 ① 회사는 네이버 클라우드 플랫폼(NCP)의 NAVER API HUB로의 서비스 이관에 따라, 본 약관 시행일 이후인 2026년 7월 30일 24:00를 기점으로 네이버 개발자센터를 통한 'Search API', 'Search Trend API', 'Shopping Insight API'(이하 "이관 대상 API")의 신규 이용 신청 접수를 중단합니다.
>
> ③ 제1항 및 제2항의 규정에도 불구하고, 네이버 개발자센터를 통한 'Search API' 중 '쇼핑', '책', '학술정보' 데이터 제공 서비스는 2026년 7월 31일 24:00부로 종료됩니다. 해당 서비스 종료 시점 기준 기존 이용자라 하더라도 2026년 8월 1일 00:00부터는 해당 API를 더 이상 이용할 수 없습니다.

- 옮겨 간 곳인 NAVER API HUB 문서(https://api.ncloud-docs.com/docs/naver-api-hub-overview)의 검색 API 목록은 뉴스·백과사전·블로그·웹 문서·이미지·지식iN·지역·카페글 등이고 **쇼핑(상품) 검색은 없어요.** "쇼핑 인사이트"는 클릭 추이 통계라 가격을 주지 않아요.
- 같은 내용의 보도·안내: https://www.tokenpost.kr/news/ai/403521 , https://wikidocs.net/461908 , https://brunch.co.kr/@ainote/123
- 키 없이 `shop.json`을 불러 보면 401 `{"errorMessage":"Not Exist Client ID : Authentication failed. (인증에 실패했습니다.)","errorCode":"024"}`가 와요. 주소 자체는 아직 응답하지만(블로그 검색도 같은 응답), 유효한 키로 쇼핑 검색이 되는지는 키가 없어서 확인하지 못했어요. 약관대로라면 안 돼요.

검색 API 특약(같은 약관 "나. 2. 네이버 검색 API 서비스")도 알아 둘 내용이에요. 다른 검색 API를 쓰게 되더라도 적용돼요.

- 2.1 "이용자는 네이버의 BI 가이드에 따라 애플리케이션 등에 해당 데이터가 네이버 검색결과임을 표시하여야 합니다."
- 2.2 "검색결과의 앞, 뒤, 중간 등에 다른 내용을 삽입하거나, 순위 및 내용을 수정, 변조 또는 왜곡할 수 없고 … 데이터 원본의 출처를 표시하고 원본으로 이동할 수 있는 링크를 제공하여야 합니다."
- 2.3 금지: "데이터(…)를 복사, 저장 또는 캐싱하는 행위 (단, 2.4.에 해당하는 경우 제외)", "데이터를 AI에 입력하거나 학습, 개선, 평가 및 노출 등에 활용하는 행위", "검색결과가 표시되는 페이지에 광고를 표시하거나, 기타 검색 API 서비스를 활용하여 수익을 얻는 행위".

이 때문에 `server/shop.js`는 처음 계획과 다르게 **결과 순서를 바꾸지 않고(오늘의집 상품을 앞으로 올리지 않음), 서버에 결과를 저장(캐시)하지 않아요.** 그리고 이 결과를 AI 조언(`/api/advice`) 프롬프트에 넣으면 안 돼요.

## 6. 쿠팡 파트너스 API 등 다른 후보

- **쿠팡 파트너스 오픈 API**: 상품 검색 API가 있고 HMAC 서명(ACCESS_KEY, SECRET_KEY)을 써요. 파트너스 가입과 "최종 승인" 뒤에 쓸 수 있다고 알려져 있어요(공식 문서 원문은 확인하지 못했고, 외부 글 기준이에요. 공식 안내: partners.coupang.com 의 오픈 API 도움말). 승인 심사가 필요해서 대회 당일에는 어렵고, 쿠팡 상품만 나와요. 구현하지 않았어요.
- **11번가 오픈 API**: 상품 검색 API가 있었던 것으로 알려져 있지만 지금 상태와 발급 절차를 확인하지 못했어요. 구현하지 않았어요.

## 8. 지금 동작하는 것 / 키가 있어야 하는 것

**키 없이 지금 동작해요**

- `shopLinks(query)` → `[{ id: 'ohouse', label: '오늘의집', url }, { id: 'naver', label: '네이버쇼핑', url }, { id: 'coupang', label: '쿠팡', url }]`. 한글은 UTF-8로 인코딩하고, 제어 문자는 빼고, 50자를 넘으면 잘라요. 빈 검색어면 `[]`.
- `fetchShop(query)` → 지금은 항상 `null`(서버가 503). 처음 503을 받으면 그 화면에서는 서버에 다시 묻지 않아요. 화면은 `null`이면 링크만 보여주면 돼요.
- `GET /api/shop?query=` → 503 `{ error }`, `/api/health`의 `shop`은 `false`.

**키가 있어야 해요 (그리고 네이버가 쇼핑 검색을 다시 열어야 해요)**

- `GET /api/shop?query=책상` → `{ items: [{ title, price, url, image, mall }] }` (최대 5개, 네이버 순서 그대로, `<b>` 제거, 가격은 숫자, https 주소만).
- 응답: 키 없음 503 / 검색어가 1~50자가 아님 400 / 네이버 오류·시간 초과(5초) 502 / GET이 아님 405.

### 네이버 키를 받는 방법과 넣는 곳

먼저 알아 둘 점: 5절대로 **지금은 검색 API 신규 신청이 닫혀 있고 쇼핑 검색은 종료**됐어요. 아래는 네이버가 다시 열거나, 이미 받은 키로 시험해 보고 싶을 때를 위한 기록이에요.

1. https://developers.naver.com 에 네이버 아이디로 로그인해요.
2. 메뉴에서 **Application > 애플리케이션 등록**을 눌러요. (처음이면 이용약관 동의 → 휴대폰 인증)
3. **애플리케이션 이름**에 `방꾸미`처럼 적고, **사용 API**에서 **검색**을 골라요.
4. **비로그인 오픈 API 서비스 환경**에서 **WEB 설정**을 추가하고 **웹 서비스 URL**에 `http://localhost`를 적은 뒤 **등록하기**를 눌러요.
5. **Application > 내 애플리케이션**에서 방금 만든 이름을 누르면 **개요** 탭에 **Client ID**와 **Client Secret**(**보기** 버튼)이 나와요.
6. 프로젝트 폴더(`C:/Users/사용자\dev\방꾸미`)에 메모장으로 `.env.local` 파일을 만들고 두 줄을 적어요.

   ```
   NAVER_CLIENT_ID=여기에_Client_ID
   NAVER_CLIENT_SECRET=여기에_Client_Secret
   ```

   (또는 서버를 켜기 전에 같은 이름의 환경 변수로 넣어도 돼요. 환경 변수가 먼저예요.)
7. 서버를 다시 켤 필요는 없어요(요청마다 읽어요). 화면은 새로 고쳐 주세요. `http://localhost:5174/api/health`에서 `shop: true`가 보이면 키를 읽은 거예요.

키는 서버(`server/shop.js`)만 읽고 브라우저로 보내지 않아요. vite 개발 서버가 `/.env.local` 요청을 403으로 막는 것도 확인했어요. 이 파일은 다른 사람에게 주거나 제출물에 넣지 마세요.

### 화면 통합 담당에게

- 가격 표시는 지금처럼 "시연용 예상 가격"을 기본으로 하고, 가구·소품마다 `shopLinks(spec.query)` 링크를 `target="_blank" rel="noopener noreferrer"`로 달아 주세요.
- `fetchShop` 결과를 쓸 때는 "네이버 쇼핑 검색 결과"라고 출처를 적고, 제목은 글자로만 표시해 주세요(HTML로 넣지 않기).
